# 自适应派发：真实联调记录

> English: [../adaptive-validation.md](../adaptive-validation.md)

2026-09-17，在 macOS 上使用 Herdr 0.9.0、Claude Code 2.1.274 和 Pi 0.85.1 验证了真实自适应派发。这是功能集成检查，不是与直接 Codex 的性能对照。

| 配置 | 实际结果 |
| --- | --- |
| Pi，已配置的 Kimi `k3` API provider | 读取任务、修改夹具、调用工具、提交报告、独立验收、集成和清理均通过 |
| Claude Code，`fable` 别名经过已有代理；隔离短探针返回 `grok-4.6` | 同样完成完整流程，完成证据来自原生 hooks |
| Claude Code，启用一个原生 Explore 子代理 | 观察到同一 id 的 `SubagentStart` 和 `SubagentStop`；报告包含真实已完成的 child id，独立验收与集成通过 |

每个成功场景使用可丢弃的已提交 Git 夹具和独立 worktree，集成前原项目内容保持不变。worker 已关闭，运行容量已释放，专属 Herdr 服务已停止。原有 Claude settings 以及 Pi settings/models/auth 文件前后摘要一致。配置和历史目录已隔离，只复用明确选择的 API 认证，没有导出 OAuth。Pi 用户扩展和项目定制发现功能在这次限定检查中被禁用，不能据此宣称所有用户的日常定制环境或其他 provider 都已验证。

联调发现并修复了两个真实环境故障：

- Herdr 内的登录 shell 改写 PATH，导致预检发现的 Agent 与实际启动的版本不同。Pi 使用了 Node 18，Claude 指向旧二进制。现在每个专属终端在启动前都恢复已发现可执行文件所在目录，包括从 PATH 发现的安装。
- 重新加载状态目录时，macOS `/var` 与 `/private/var` 别名导致遥测目录归属检查失败。现在加载运行前会解析既有状态根的真实路径。

独立评审还复现了一个容量泄漏：Claude 终端已启动，但任务尚未发送。现在取消时，确认 worker 关闭后即可释放容量；已发送任务或提交后仍未知的子代理继续阻止释放。上述边界均有离线回归。启动失败的尝试保留为失败记录并清理其专属运行资源，没有计入成功试验。

浏览器检查使用真实成功运行的元数据，覆盖中英文桌面和窄屏布局、选中资源、阶段时间、已报告与已验证的子代理证据、已知子代理数量和缺失用量。HTTP 再次净化会保留子代理计数及计时覆盖信息，看板没有新增终端或推理正文。

## 待补证据与默认上线

2026-09-18 的后续检查新增了两个隔离 Pi/Kimi 场景：冷启动自适应派发先运行一个受预算约束的 quick probe，再完成任务交付；普通 delegated 原生任务通过独立验收后写入 `verified-task` 就绪证据，后续只读自适应选择无需探针即可采纳。Pi 首次启动写入隔离配置中的版本提示信息，指纹变化正确阻止了将结果归属到旧配置；配置稳定后，回流验证通过。OAuth 证据复用目前由离线凭据形态测试覆盖，尚未实测真实 OAuth 套餐。专属会话及隔离认证副本均已清理，原生用户配置和正常历史未变化。

自适应保持显式启用。以上检查不能证明跨 Agent 质量排名、节省的延迟、所有 provider 的完整取消/故障覆盖、Pi 原生子代理能力或大型项目完成率提升。Pi 子代理完成仍使用明确标注的报告合同。更大的真实任务、受控修复/取消场景，以及已有项目和从零项目的配对试验仍属于发布工作。

[配对评估器](benchmark-evaluation.md)用于统计预先登记的试验，失败和缺失结果同样计入分母。它是离线统计工具，不负责启动 Agent 或验证证据真伪。不能用这三个冒烟成功代替多任务试点，也不能据此默认启用自适应。

需要回退新任务的策略时，在相应对话执行 `node bin/harnessorbit.mjs mode enable --strategy delegated --calibration-policy off`。运行中的尝试保留原路由绑定；策略切换不会停止或替换它们，仍需正常验收，或明确取消并清理。
